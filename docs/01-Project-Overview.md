# 1. Project Overview

## The problem

The Rule Check Tools are small DSi applications (~2 MB each). Inserted next to a Pokémon cartridge, they read the
cartridge's save data and report whether the party and Battle Box are tournament-legal. The apps load three files
from the SD card, and none of them shipped with the apps:

| File | Size | Purpose |
|---|---|---|
| `sdmc:regulation.cfg` | 13 bytes | Which checks are switched on; which cartridge versions are accepted; whether to log |
| `sdmc:regulation.bin` | ≥ 180 bytes | The tournament's rules: banned species/items, level rules, duplicate clauses |
| `sdmc:rule.prd` | 386,940 bytes | The legality table: allowed moves, minimum levels, allowed locations, item whitelist |

A community group in 2019 had gotten the PWC2010 app to boot, but could not make it run a real check because these files
were missing. The goals for this project were: **(1)** work out what each file is, **(2)** rebuild usable versions, **(3)** build a test
party of illegal Pokémon, and **(4)** document every error code the log viewer shows.

## Results at a glance

| Goal | Outcome |
|---|---|
| Understand `regulation.cfg` | **Fully resolved.** 13 bytes; bytes 0, 1, 4–10 and 0x0C are read; all others are ignored. Same in both apps. |
| Understand `regulation.bin` | **Mostly resolved.** Fields at 0x0A, 0x0C–0x11, 0x12–0xB3 decoded and verified in an emulator. Bytes 0x00–0x09, 0x0B, 0x0F are never read (purpose unknown). |
| Understand `rule.prd` | **Resolved.** Item whitelist + 667 records × 0x244 bytes; every field the checker reads is decoded. Some flag bits are unnamed (see [Open Questions](12-Open-Questions)). |
| Rebuild `rule.prd` | **Done for the move data**, from PokeAPI, matching the original table to 99.95 % of cells. Event-move bits, flags, minimum levels and location lists are carried over from the table compiled into the app. |
| Test party | **Done.** 6-Pokémon illegal party + 20 extended cases (26 files); every expected code reproduced by the app's own checker in an emulator. |
| Real-hardware check | **Partial, and strong.** Two logs from a real DSi (rule check run with this project's files) agree with the emulator on **16 / 16** Pokémon, including a BW2-tutor move that distinguishes the BW2 table from the older one. See [Log Files and Viewer](13-Log-Files-and-Viewer). |
| Error code reference | **Done.** 72 code rows, message text taken from the app itself; 53 triggered and confirmed, 14 shown unreachable by construction, 4 with a message but no code path found, 1 read-only. |

## What was not possible

* **Hardware validation is partial.** Most verification is by emulating the apps' own ARM9 code
  (see [Methodology](02-Methodology)); one real DSi run (two log files) has since confirmed the config files, the
  `rule.prd` verdicts and `regulation.bin`'s minimum-count field.
* The original `rule.prd` / `regulation.bin` used at the real tournaments were not available, so the rebuilt
  files are *functionally equivalent reconstructions*, not copies.
